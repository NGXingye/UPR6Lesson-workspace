# 超规处置

发现文档或源码超出规范时用本文件。**按表改，任务做完再一次性汇报。禁止中途打断报备，禁止为过关临时改文件。**

## 一律禁止

- 为贴规范去重构未点名的遗留文件（「顺手整理」）。
- 临时绕过：`v2`/`final`/`copy`/`tmp`、注释掉违规代码、把超长文件改成更低读取等级、抬高行数上限、把契约数字再抄一份。
- 用 `Shader.SetGlobal`、第二套默认值、`#if` 假分支掩盖缺失依赖。
- 规范与源码冲突时用文档覆盖源码。

## 怎么改（跟任务走）

本任务正在改的文件、以及契约要求必须成对改的双端文件（C#↔HLSL、IDs↔Binder）：直接按下表收口。

未点名的邻居超规：不改，只在收工报告里记一条，必要时写入该模块 `roadmap.md`。

只有「用户要的结果在不越权、不绕过的前提下做不到」时才把 `task_status` 设为 `blocked`。普通超规不要 blocked，不要中途停下来问。

## 文档超规

按序，禁止跳到抬上限或重写全文：

1. 删空话、翻译式重复、与 `_index` 重复的节。
2. 同责两节合并，只留一处事实。
3. 溢出内容改成链接到已有唯一来源。
4. 仍放不下：用五问拆新文件并登记 `_index`。禁止 `v2` 副本。

YAML 与 Markdown 重复：目录留 `modules.yml`，边界留 profile，知识留 md。

## 源码超规

按序：

1. 正在改的文件超软顶：本任务内按 `ClassName.Feature.cs` 或模块已有方式拆。
2. 超硬顶：同样拆开，不要继续往同一文件堆。禁止抬硬顶。
3. 重复定义 / 散写 `"_Xxx"` / 双份魔法数：收到模块唯一权威。成对改不算越权。
4. 未点名的遗留超规：只写 `roadmap.md`，本次不改。

契约写死（IFFT 1024、BladeStride 18）不是超规；同一数字两处会漂才是。

## 收工再报

最终回复里用一小段说清即可，不要另开任务卡：

- 按流程改了哪些超规（文件 + 做了哪一档处置）
- 哪些遗留只记了 roadmap、没动
- 若 `blocked`：缺哪次用户点名、卡在哪条规则

然后把 `task_status` 收成 `idle`（或保持 `blocked`）。不要留临时文件。
